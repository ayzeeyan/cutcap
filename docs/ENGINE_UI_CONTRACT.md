# UI–engine contract, version 1

The Rust source of truth is `crates/cutcap-contracts`. `CONTRACT_VERSION = 1` identifies this in-process protocol; no network, plugin ABI or compatibility across independently shipped binaries is promised. Project schema version is separate. Contract edits require producer/consumer/test/doc updates and an explicit compatibility decision.

## Requests and responses

`CommandEnvelope { request_id, project_id, command }` transfers an owned message. Request IDs are fresh non-nil UUIDs generated by the app; callers must not reuse IDs. Project ID is required for every command except NewProject. The worker rejects stale/missing project scope with StaleProject; queued actions from an old project cannot modify a replacement. NewProject atomically installs a complete valid replacement and clears selection. Invalid replacement requests preserve the old project.

Each submitted command is either rejected locally by `try_send` (Busy/Internal; not accepted), or receives exactly one terminal `EngineEvent::Completed { request_id, snapshot }` or `Failed { request_id, error }` while the session remains live. Window/process teardown closes the transport; outstanding requests may then be abandoned. There is no durable queue or exactly-once retry/deduplication promise. The coordinator tracks pending IDs, removes them on terminal results and clears them on disconnection.

| Command | Phase 0 behavior |
|---|---|
| NewProject { name } | Create in memory, with Video 1 / Audio 1 empty tracks |
| GetSnapshot | Return current view state |
| AddTrack { kind } | Append validated named track and select it; limit 128 |
| Select { selection } | Validate None/Track/Clip against this project; return updated selection |
| OpenProject { path } | Unsupported; no file read |
| ImportMedia { paths } | Unsupported; no probing/decoding |
| RemoveClip { clip_id } | Unsupported; no model mutation |
| Seek { position }, SetPlayback { playing } | Unsupported; no invented position or playing state |
| Undo, Redo | Unsupported; no history stack |
| StartExport { destination }, Cancel { target } | Unsupported; no files/jobs created |

Reserved shapes make unavailable operations explicit, not stable promises about future options. No public UI dispatches them as successful features. A future OpenProject path should be app-scoped; changing the current conservative project-scope rule must be intentional.

Completed contains a small `ProjectSnapshot`: ID/name/timebase, track summaries, counts and session selection. It is not a mutable Project or persistence DTO. Decoded data never travels here. Failures carry a typed `ErrorCode` and actionable message; current codes are Unsupported, InvalidInput, NotFound, StaleProject, Busy and Internal. Recoverable failures preserve previous model state and appear in the status area and tracing log. No background error is silently turned into success.

## Thread ownership and backpressure

- **UI/main thread:** all Slint components, callbacks, weak-handle upgrades, view models, panel geometry and keyboard handling. `Rc<RefCell<ViewState>>` is local to this thread, never shared with the worker.
- **Command worker:** owns `Engine`, its Project and SelectionState. Sequential model operations provide ordering. It receives owned envelopes, creates owned events, and accesses no Slint objects.
- **Transport:** `std::sync::mpsc::sync_channel` in both directions, capacity 32 each. UI `try_send` cannot block. A worker `send` can wait for result capacity. The 33 ms UI timer drains at most eight events per tick, so idle polls allocate no event batch. Snapshot/model allocations occur only on model results.
- **Shutdown:** after `window.run()` returns, stop the timer, drop results before requests, then join the worker. This order is tested with saturated queues. A worker panic/disconnection is surfaced; there is no automatic restart pretending to preserve state.

The timer's interval is coordination latency, not a playback clock or measured responsiveness guarantee. No async runtime, global event bus or shared model mutex is needed for this phase.

## Extension rules for media milestones (planned, not implemented)

Long operations must dispatch to separate bounded workers so the command owner remains responsive. An accepted job should return its job identity promptly. Progress events correlate with that job/request and describe stage + completed units + optional total; an unknown total must not generate a fictional percentage. Progress can be coalesced on a separate bounded path. Reliable terminal completion/failure/cancellation must not be dropped. Define these concrete event DTOs when the first job is implemented, with units, monotonicity and tests, instead of introducing unused job machinery now.

Cancellation uses the reserved `Cancel { target }` request shape. Before implementing it, define cooperative cancellation points, ownership of child processes, partial-output cleanup, completion/cancel races, stale target errors and the terminal Cancelled outcome. Cancel currently returns Unsupported. A cancellable worker must not keep the command loop occupied until its I/O completes.

For seeks, attach a generation/request identity so late frames from a superseded seek cannot replace the newest image. A latest-frame mailbox is distinct from reliable project events and bounded by bytes as well as count. Workers own CPU buffers or native resources; only the UI adapter creates/assigns Slint images on its event-loop thread. Document format, dimensions, stride, color interpretation, timestamp mapping and resource lifetime before carrying real frames.

Undo/redo will wrap atomic model transactions. Persistence will validate a bounded temporary document and commit only after full validation/migration. Export will consume an immutable project/evaluation snapshot and share semantics with preview, while owning its own output/job lifecycle. Pixel coordinates, window sizes and preview FPS never become authoritative editing data.
