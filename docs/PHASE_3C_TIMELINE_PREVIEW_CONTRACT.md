# Timeline preview contract — Phase 3C / ABI 5

Core schema and project envelope remain 1. ABI/contract 5 add transient Source/Timeline monitor selection and timeline seeking; edited-sequence Play remains unavailable. Rust alone evaluates clips and owns the timeline position. Source commands retain source semantics and never move the timeline playhead.

The monitored track is the selected video track, otherwise the selected clip's video track, otherwise the first video track in project order. Audio is ignored. The viewer names this single track; this is not compositing. Seeking the ruler switches to Timeline. Leaving Source pauses its transport, retaining position/epoch and bounded preroll; returning does not auto-play. Source still-frame requests and timeline frames share the existing latest decoder. Only the selected mode's frame is exposed to the one frontend bitmap.

An indexed Rust evaluation uses `[start,end)`. Exact cuts belong to the next clip; empty regions return Blank without decoding. Source mapping is `ceil(source_in + (position-start) * project_timebase)` in the selected stream's tick clock: combine exact rationals before rounding once. The exclusive source endpoint is the ceiling of `source_in + duration`; decoded original stream ticks must be >= requested and < that endpoint. A frame in a different clock must rescale exactly to original stream ticks or fail validation. This preserves the existing ceiling source-frame policy, including VFR/nonzero/negative PTS, without leaking a successor frame past a short clip's end. If no qualifying frame exists, show an explicit no-frame-in-clip state; never substitute another clip or fabricate PTS.

The owner builds a per-track sorted index lazily after geometry edits/Open, then uses binary lookup. Evaluate returns a small correlated result, never a ProjectSnapshot/clip vector. Its project identity, transient document-generation UUID and request identity gate decoding. A single latest desired seek, one in-flight evaluation, and the existing active/pending/completed decoder bound work. Mutations, selection/track changes, relink, project replacement and mode changes invalidate incompatible work. Reliable document events remain separate from ephemeral preview results.

ABI controls are nonblocking: set_preview_mode (0 Source / 1 Timeline), seek_timeline (exact i64 project ticks), seek_timeline_ms (floor-rescaled UI milliseconds), seek_timeline_text (existing millisecond/timecode grammar plus an explicit `ticks` suffix), cancel_timeline_preview. New consumed monitor DTO fields require version 5 in Rust/C# together; FrameInfo stays 24 bytes and pixels stay outside JSON. Both positions, readiness, actual source PTS, monitored track and evaluation/decoder timings come from Rust. Timeline seek/mode/monitor state is transient and never dirty/history/persistence data.

The native source frame and at most one timeline frame can coexist (each <=3,686,400 bytes); no second frontend bitmap/cache is added. Frame generations share one session counter and are renewed on mode restoration. Mode switches invalidate old copy permissions. UI displays Evaluating/Loading/Ready/Blank/Unavailable/NoFrame/Failed/Cancelled honestly. Native due-frame deadlines and source playback scheduling are unchanged.
